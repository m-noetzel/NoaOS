## Greatest Risk
The iOS package still has no @main entry point. With iOS6 adding PushNotificationService and DeviceService on top of the existing auth/chat stack, there are now 8+ service actors (APIClient, AuthService, ChatService, PushNotificationService, DeviceService, KeychainService, plus ViewModels) that have never been instantiated together. Each works in isolation with its own mocks, but nobody has verified they compose correctly -- that the token provider passed to APIClient is the same AuthService used by AuthViewModel, that DeviceService gets the same APIClient as ChatService, etc. The first real app build (iOS11) could reveal initialization order issues, retain cycles, or actor reentrancy that the current test suite cannot detect. Every phase that adds a new service without an app target deepens this gap.

## Decisions Needed
- Consider creating a minimal App target before iOS11 to catch wiring issues early. Each additional service actor makes late discovery more expensive.
- The mr7_smoke integration test still fails (KeyError). Decide whether to fix it now or accept it as known debt for Wave 15C.
