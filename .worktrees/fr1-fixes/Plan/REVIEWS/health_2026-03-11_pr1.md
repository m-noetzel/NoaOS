## Greatest Risk
**MemoryStore.store() does not set user_id on facts.** PR1 correctly added user_id filtering to the read path (list_all, get_by_id, update_status, delete), but the write path (store(), called by the orchestrator's _handle_remember) never sets user_id. Result: any fact stored through normal conversation flow is invisible to the Memory Audit UI. The user sees an empty memory page despite facts existing. This disconnect between write-path and read-path is the single biggest functional risk because it silently breaks the memory feature end-to-end. Should be addressed in PR4 (MemoryStore interface cleanup).
