## Greatest Risk
**Composition failure in iOS11.** The package now has 12+ actors, 5+ ViewModels, and 0 production wiring. iOS11 is the first and only phase that composes everything into a running application. Every orphaned component from prior phases (VPNStatusBanner, VPNService, OfflineIndicator, CertificatePinningDelegate) must be wired simultaneously. If composition reveals deep issues (actor reentrancy, MainActor deadlocks from DispatchSemaphore patterns, circular dependencies), there is no buffer phase for rework. This risk has been flagged since iOS8 and grows with each new isolated component.

## Decisions Needed
- Consider a minimal composition smoke test (instantiate all services in one test) before starting iOS11's full integration work. Finding reentrancy or init-order issues early saves significant rework.
- The placeholder SPKI hash in PinnedCertificates.swift must be replaced before any production deployment. Decide whether this is an iOS11 deliverable or a separate deploy-time task.

## Risks You Are Taking
1. **Certificate pinning is not active.** CertificatePinningDelegate exists and is tested, but zero URLSessions use it. Until iOS11 wires it, all network connections are MITM-vulnerable to any CA-signed certificate. This is the status quo from iOS3 but is now more visible because the fix exists but is disconnected. Impact: high if the app were deployed today. Likelihood of deploying before iOS11: low.

2. **iOS11 is overloaded.** It must wire CertificatePinningDelegate into all 4 URLSession sites, compose 12+ actors, add VPNStatusBanner to views, write E2E integration tests, add accessibility, dark mode, error states, app icon, and launch screen. This is the most complex phase in Wave 15C, yet it was estimated at only 45 minutes. If prior phases are any guide (iOS3 estimated 60min took 90min, iOS5 estimated 60min took 90min), iOS11 will take significantly longer.

3. **DispatchSemaphore deadlock potential.** VPNService.launchViaSystem blocks a cooperative thread waiting for MainActor. In the worst case (saturated thread pool + busy MainActor), this is a deadlock. In practice, unlikely for a single call, but it sets a bad precedent. Impact: app hang. Likelihood: very low.
