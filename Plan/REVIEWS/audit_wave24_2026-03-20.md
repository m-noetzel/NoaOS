## High Findings (fix soon)

### W24-H1: Langfuse env vars not configured in noa-api service (LF1 wiring gap)

**Severity**: HIGH
**Location**: `docker-compose.yml` lines 76-93 (noa-api environment block)

The `langfuse_client.py` checks for `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` environment variables to enable observability. These are **not passed** to the noa-api service in either `docker-compose.yml` or `docker-compose.dev-full.yml`. The langfuse service itself is correctly configured (lines 273-288), but the API server will never connect to it.

**Impact**: All Langfuse instrumentation (trace creation, generation spans, tool spans, eval scores) silently no-ops. The Traces page iframe will load Langfuse UI but show zero data from Noa.

**Fix**: Add to noa-api environment:
```yaml
- LANGFUSE_PUBLIC_KEY=${LANGFUSE_PUBLIC_KEY:-}
- LANGFUSE_SECRET_KEY=${LANGFUSE_SECRET_KEY:-}
- LANGFUSE_HOST=http://langfuse:3000
```

## Cross-Phase Integration Analysis

### Graph Topology (Wave 24 core)

The orchestrator graph correctly chains all new nodes:

```
router -> classifier -> planner -> agent -> tools/responder -> evaluator -> __end__/agent
```

- **classifier** (DI1): Reads last user message, outputs `task_type`. Falls back to "execution" on error.
- **planner** (OI1): Reads `task_type`, selects archetype, generates plan. Skips for simple_utility.
- **evaluator** (EV1): Scores response post-responder. Reroute injects feedback, max 2 cycles. Persists to DB.
- **agent** (LS1): Streaming via callback. ReAct thoughts parsed when `use_react=True`.

### Data Flow Integrity

1. **task_type**: Set by classifier -> read by planner (archetype selection), evaluator (dimension selection), runner (Langfuse metadata)
2. **plan/archetype/use_react**: Set by planner -> read by agent (system prompt injection, ReAct mode)
3. **eval_scores/eval_verdict/eval_cycle**: Set by evaluator -> read by graph conditional edge, runner (Langfuse scores)
4. **run_id**: Set in initial_state -> read by evaluator (DB persistence), runner (event persistence)
5. **llm_usage**: Accumulated by agent -> read by runner (Langfuse generation spans, result_ready event)
