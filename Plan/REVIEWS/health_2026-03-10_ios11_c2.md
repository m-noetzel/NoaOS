## Risks You Are Taking
1. **Certificate pinning not wired (medium impact, certain).** CertificatePinningDelegate exists but is not connected to any URLSession. All iOS network traffic is unprotected against MITM. Deferred from iOS10 to iOS11 and still unresolved. The delegate code is correct (SPKI DER hash, tested in iOS10) -- it just needs to be passed to URLSession configurations in APIClient and SSEClient.
2. **Chat SSE integration untested (medium impact, moderate).** ChatFlowTests prove the concept but not the implementation. A bug in SSEClient's event parsing or ChatViewModel's accumulation logic would not be caught by current tests. The 72+ unit tests with mocks reduce this risk but don't eliminate it.
3. **Approval flow is entirely stub (medium impact, moderate).** Both pending (returns []) and decide (hardcoded response) endpoints are stubs with no DB persistence. iOS approval UI exercises only stub responses. Tracked as iOS11-M1 and iOS11-M2.
