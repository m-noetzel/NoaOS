## Greatest Risk
The "wired in class, not used" anti-pattern is now on its third recurrence (QC5, QC8, HD). Each time, a class or method is implemented, tests pass via mocking, and the production code path never executes the new code. The PostgresCheckpointer is stored on the runner but `save()`/`load()` are never called. GovernanceWrapper accepts `user_id` but has zero callers. The root cause is that there are no integration tests that exercise real end-to-end paths, so dead code passes review. Until at least one integration test calls the chat pipeline end-to-end (message in, events out, DB rows created), every "fix" risks being decoration.

## Risks You Are Taking
1. **Plaintext OAuth tokens in Postgres** -- if the database is compromised (SQL injection, backup leak, unauthorized access), an attacker gets full Google API access to the user's calendar and email. Likelihood: low in single-user LAN deployment. Impact: high.
2. **Replay endpoint authorization gap** -- any authenticated user can read any other user's run events by enumerating UUIDs. In a single-user system this is moot, but multi-user support would make this an information disclosure vulnerability. Likelihood: low now. Impact: medium.
3. **Test suite is red** -- 3 regressions from this commit on top of the 14 pre-existing failures means 17 failing tests. The green test gate is not enforcing anything if failures are allowed to accumulate. Likelihood: certain. Impact: erodes confidence in all future changes.
