If iOS11 reveals deep wiring problems, all 10 preceding phases may need rework.

## Risks You Are Taking
1. **No app composition test (high impact, high likelihood).** 10+ actors tested only in isolation. First real composition happens in iOS11, the final phase. Composition failures (retain cycles, actor deadlocks, MainActor violations) would cascade across all prior phases. Likelihood: moderate -- Swift 6 strict concurrency catches many issues at compile time, but runtime composition is untested.
2. **Voice chat mode is a stub (medium impact, certain).** `voice.py` lines 123-134 return a random `thread_id` without invoking the chat pipeline. Any user selecting chat mode gets a fake thread that does not appear in their thread list. Low risk until the feature is surfaced in the iOS UI, but the mismatch between API contract and behavior should be explicitly documented or gated.
3. **Refresh token cleanup missing (medium impact, moderate likelihood).** AuthService.refresh() does not clear Keychain tokens on failure. A stale refresh token causes repeated 401s until the user manually logs out. Affects all authenticated API calls including voice upload.
